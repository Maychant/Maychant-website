# Maychant repository influences

Research date: November 4, 2026 (America/Detroit). All eleven requested unique repositories were accessed. GitHub README content, repository metadata and the specific linked source files or public pages below were inspected. This document records proposed applications, not a claim that every influence has already been implemented. No site files were changed in this research task.

The design direction is a substantial, photographic succession service: an owner’s working business, a clear handover story, a concrete preparation deliverable and a small, credible next step. The repository collection supplies different inputs to that design; it does not require eleven dependencies or eleven competing visual styles.

## Recommended visual composition

1. **Opening scene:** A large editorial headline and brief proposition over or beside an authentic small-business photograph. One primary CTA and one sample-file link. Establish the brand with scale, crop and typography. Keep the content visible immediately; a short entrance sequence can enhance it.
2. **A business is more than its owner:** A full-width photographic transition gives way to a short, concrete explanation of undocumented operating knowledge, incomplete records and an uncertain next decision. Avoid invented market statistics or logos.
3. **Three chapters of preparation:** Numbered sections explain the work. On wide screens, a sticky visual can change as the adjacent chapters enter view. On phones and with reduced motion, show ordinary stacked sections. This pinned composition is a bespoke synthesis of the references, not a claim that a particular reviewed repository contains it verbatim.
4. **Show the output:** A large preparation-file preview with source references, open questions and a next-action summary. Label demonstration content clearly. Let the visitor inspect an artifact instead of relying on unsupported testimonials or dashboard decoration.
5. **Two audience paths:** Owners see what to prepare and what the initial conversation covers; advisers see scope, review responsibility and how to propose a case. Both paths remain on one coherent site.
6. **FAQ and close:** Simple keyboard-operable disclosure rows, clear limits and a final useful CTA. The footer should finish the visual story rather than introduce a large secondary navigation system.

## Motion implementation notes

- Use one signature scroll composition. Repeated large reveals on every line will compete with the business narrative.
- The sampled PaulleDemon code moves elements by a full width/height and initially hides them through JavaScript. Maychant should use smaller motion for reading copy and preserve visible content if JavaScript fails.
- The Cruip source contains an infinite gradient headline. Its hierarchy is useful; that effect is not needed for Maychant’s service identity.
- The Magic UI files provide compact patterns, but reduced-motion handling is an implementation responsibility. Disable blur, parallax and transforms for that preference; leave the same information and controls available.
- Avoid scroll-jacking. Native page scrolling, meaningful anchor destinations and a readable static order make the cinematic sequence usable across devices.
- If continuous decorative motion or autoplay media is introduced, provide appropriate pause behavior and a static alternative. Avoid costly video merely to imitate a reference screenshot.
- Verify every interaction with keyboard navigation, visible focus, Escape/focus return for dialogs, mobile layout and reduced motion. A component’s accessible foundation does not prove the resulting page is accessible.

## Implementation accounting

The bespoke build now translates all eleven references into the following concrete choices. These are design and behavior influences, not installed dependencies or copied template source.

1. **PaulleDemon:** large service typography, original photographic transition, and staged GSAP entrances in `dist/index.html`, `styles.css`, and `app.js`.
2. **nordicgiant2:** meaningful section anchors and varied image/copy rhythm, with a single-column mobile reading order.
3. **guilyx:** tangible, clearly marked example plan, reinforced by an actual downloadable visitor plan instead of invented testimonials.
4. **AstroWind:** responsive content structure, eager hero image, local optimized assets, and an explicit reduced-motion alternative. The centered hero was selected for Maychant instead of copying Hero2's split composition.
5. **Cruip:** heading → concise copy → two clear actions → cinematic media hierarchy and staggered entrance timing. All source and imagery are original; no template redistribution.
6. **Emma Bostian design inspiration:** a three-chapter handover narrative with restrained progress and expressive typography.
7. **Emma Bostian developer portfolios:** immediately distinct audience identities, expanded to owners, future operators, and advisers.
8. **shsfwork:** one substantial scroll narrative surrounded by quieter sections; a genuine playable brand film adds depth without scroll-jacking.
9. **darelova:** deliberate display/body hierarchy, contrast-aware palette allocation, focus outlines, and accessibility review.
10. **shadcn:** native `dialog` and `details` reproduce the reviewed semantic/focus/disclosure principles in a dependency-light build. These are custom native implementations, not shadcn components installed in React.
11. **Magic UI:** a thin reading-progress line and restrained viewport-triggered reveals, with pause and reduced-motion handling added explicitly.

The user's repeated URLs were deduplicated. Curated galleries are research sources; bundling their unrelated templates would not be a coherent use of them.
